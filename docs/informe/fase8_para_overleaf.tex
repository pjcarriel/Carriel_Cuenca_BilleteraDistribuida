\subsubsection{Comprobantes Compartibles}

Al tocar un movimiento del historial, la tarjeta se despliega con la descripción de la operación (detalle, tipo, fecha y hora, número de comprobante y estado) y un botón Ver comprobante; este abre un comprobante con el monto, la fecha y hora, el número de comprobante, la cuenta, el titular y el detalle de la operación. Tras una operación exitosa el comprobante se abre automáticamente, como en las aplicaciones bancarias. Como sus datos provienen de Room, el comprobante se puede consultar y compartir sin conexión. Para compartirlo, la interfaz se dibuja dentro de una capa gráfica de Compose que luego se convierte en imagen; el archivo PNG se guarda en la caché privada de la aplicación en Dispatchers.IO y se entrega a la aplicación elegida por el usuario mediante FileProvider, que otorga un permiso de lectura temporal solo a esa aplicación (Figura~\ref{fig:comprobante}).

\subsubsection{Pago de Servicios por Cédula}

Las facturas de servicios básicos ahora registran la cédula del titular y el mes facturado. En el diálogo de pago, además del código de contrato, el usuario puede escribir una cédula, elegir el servicio y ver todas las facturas de esa persona: las pendientes primero y, en las pagadas, la fecha y la cuenta que realizó el pago (Figura~\ref{fig:pagocedula}). La cédula se valida en la aplicación y de nuevo en el servidor con el algoritmo de módulo 10 de la cédula ecuatoriana: provincia válida, tercer dígito menor que seis y dígito verificador calculado con los coeficientes 2, 1, 2, 1, 2, 1, 2, 1, 2. Las cédulas de los datos de demostración son ficticias, aunque cumplen el algoritmo, y el validador se cubrió con pruebas unitarias.

\subsubsection{Administración de Servicios en Tiempo Real}

El usuario laboratorio dispone de un panel de administración con el total por cobrar y el total recaudado, filtros por estado y por servicio, y un formulario para crear facturas; el servidor genera el código de contrato y rechaza con el código 403 cualquier intento de administración desde otra cuenta. Cuando un cliente paga una factura desde cualquier dispositivo, el servidor envía al laboratorio el aviso FACTURAS\_ACTUALIZADAS por WebSocket; el panel recarga la lista sin intervención del usuario y muestra quién pagó (Figura~\ref{fig:admintiemporeal}). Este comportamiento extiende al dominio de los servicios el mismo mecanismo de notificación en tiempo real usado para las transferencias.
